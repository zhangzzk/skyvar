SkyVar Bias Workflow: Source Properties to Halo Bias

Created 2026-05-17. This note documents what the current bias_variation code actually does when it assigns galaxy bias and then turns those per-galaxy biases into unselected and selected per-pixel b(z) maps.

Scope

The active production path does not infer intrinsic galaxy bias directly from apparent photometry. It assigns intrinsic bias from SPS stellar mass and true redshift, then uses photometric and morphology properties in the SkyVar/blending-emulator selection step. The selected bias variation is therefore selection-induced: photometry changes which biased galaxies survive, but the intrinsic per-galaxy bias is set by M_*, z, SHMR, scatter, and Tinker/Colossus.

Main implementation files: halo_bias.py, shmr.py, halo_bias.py, catalog.py, selection.py, and src/selection.py.

Catalog Standardization

The source HDF5 table is loaded, standardized, quality-cut, then passed to the bias assignment. In the active SPS run, the requested source columns include z, int_mag, abs_mag, sersic_n, e1, e2, log10_surviv_stellar_mass, and r50.

Quality cuts are applied before bias assignment:

0.05 < BA < 1.0
0 < r < 28
0.01 < Re_semimajor < 5.0
0.5 < sersic_n < 6.0

Stellar-Mass Input

The active path uses the SPS surviving stellar mass. The code converts the logarithmic SPS column to a linear mass in solar masses:

M_* = 10^(log10_surviv_stellar_mass) [M_sun]

The output diagnostic label for this path is log10_column:log10_surviv_stellar_mass. If the requested column is missing, the code raises an error. It does not silently fall back to a proxy.

Moster+13 SHMR Inversion

The code uses the Moster et al. 2013 stellar-to-halo mass relation as a median forward relation and numerically inverts it to obtain log10_mhalo_median.

Forward relation

M1 = 10^(log10 M1)
x = M_h / M1
M_*(M_h,z) = 2 N(z) M_h / [x^(-beta(z)) + x^(gamma(z))]

All masses in the SHMR module are numeric solar masses. There is no hidden h conversion in the SHMR step.

Default inverse mode: interpolation

The active default is inverse_mode="interp". The code keeps only objects with finite positive M_* and finite z >= 0. It then:

  • Builds 80 redshift nodes from the minimum to maximum valid source redshift.
  • Assigns each galaxy to the nearest redshift node.
  • Builds a halo grid in log10 M_h from 8.0 to 16.5 with 2048 points.
  • Evaluates the Moster+13 forward relation on that grid at each redshift node.
  • Uses one-dimensional np.interp in log10 M_* to recover log10 M_h.
  • Returns NaN outside the interpolation range.

Exact inverse mode

The exact alternative uses scipy.optimize.brentq on log10 M_h over [8.0, 16.5], with xtol=1e-5, rtol=1e-5, and maxiter=100. It is not the active production mode.

Halo-Mass Scatter

After the median SHMR inversion, the code applies additive Gaussian scatter in log10 M_h:

log10 M_h = log10 M_h,median + epsilon
epsilon ~ Normal(0, scatter_dex)
scatter_dex = 0.15

The RNG seed is 20260516 in the active run. The scatter is deterministic for a fixed source table order and seed. If scatter_dex <= 0, the code returns the median halo mass without scatter.

The linear halo mass stored for Colossus is then:

mhalo_msun = 10^(log10_mhalo)

Tinker+10 Halo Bias

The per-galaxy bias column is bias_tinker10. It is computed with colossus.lss.bias.haloBias using the Tinker+10 model. The SHMR mass is in numeric M_sun; Colossus expects M_sun / h, so the adapter multiplies by h:

M_colossus = M_h [M_sun] * h
bias_tinker10 = haloBias(M_colossus, z, mdef="200c", model="tinker10")

Default bias mode: interpolation

The active default is bias_mode="interp". For valid objects with finite positive halo mass and finite z >= 0, the code:

  • Builds 80 redshift nodes over the valid source redshift range.
  • Assigns each galaxy to the nearest redshift node.
  • Builds a 2048-point log10 M_h grid from max(6.0, min(logM)-0.1) to min(17.5, max(logM)+0.1).
  • Evaluates Colossus haloBias on the grid at each redshift node.
  • Interpolates linearly from log10 M_h to bias.
  • Returns NaN outside the grid.

The exact mode calls Colossus directly per valid object. It is available but is not the active production mode.

How Photometry Enters Selected Bias Maps

Once every source-row has an intrinsic bias_tinker10, the workflow simulates SkyVar pixels in the same style as the n(z) workflow. For each simulation pixel, n_pop source rows are drawn with replacement from the compact source table.

Pixel-level modification of apparent properties

  • The pixel id is set to the simulation HEALPix pixel.
  • The systematics maps set local psf_fwhm and pixel_rms.
  • The Galactic/extinction map shifts apparent magnitude: r = r + galactic_map[pixel].
  • Objects with shifted r > detec_mag_bound, with detec_mag_bound = 26.0, are marked beyond_detec_bound and skipped as classifier primaries.
  • SNR is precomputed from magnitude, size, PSF, noise, zero point, and pixel scale.
flux = 10^[-0.4 (r - zero_point)]
sigma_gal = Re / 1.678
sigma_psf = psf_fwhm / 2.355
sigma_eff^2 = sigma_gal^2 + sigma_psf^2
n_eff = 4 pi sigma_eff^2 / pixel_size^2
snr = flux / (pixel_rms sqrt(n_eff))

Classifier and detection probability

The workflow calls nz_utils.icat2cla_v2. That function builds primary-secondary neighbor features with cla_k=2, marks a source as neighbored only when the nearest secondary is within R_MAX_CLA = 3/3600 deg, converts distance to arcsec, applies data_utils.rescale_v2, and evaluates the XGBoost model to produce the detection probability.

The classified catalog keeps the primary bias as bias_tinker10_input_p. The classifier does not recompute the bias; it carries the preassigned primary bias through the selection step.

Current selection

In the active run, selection_mode="none", which means:

Map Aggregation

Bias maps are accumulated in redshift bins and statistics HEALPix pixels. If nside_sim and nside_stats differ, simulation pixels are remapped to statistics pixels by HEALPix pixel centers.

Unselected mean bias

The unselected map uses all simulated source draws that lie inside the redshift grid and have finite bias:

b_unselected(p,k) = [sum_i b_i] / [sum_i 1]
i in pixel p and redshift bin k

Selected mean bias

The selected map uses classifier-selected galaxies and weights by detection probability:

b_selected(p,k) = [sum_i detection_i b_i] / [sum_i detection_i]
i in selected galaxies in pixel p and redshift bin k

The stored delta map is:

delta_b(p,k) = b_selected(p,k) - b_unselected(p,k)

Count and sum-weight maps are stored beside the mean maps: count_unselected_z, count_selected_z, sum_weight_unselected_z, and sum_weight_selected_z.

What the Source-Property Plots Show

The source-property diagnostic plots are made immediately after the per-source bias assignment, before the expensive pixel classification loop. They show the source catalog relation between assigned bias, assigned stellar mass, photometric properties, and morphology. For large catalogs they use a deterministic subsample for readability.

  • *_source_bias_vs_photometric_properties.png: linear-y scatter of bias_tinker10 versus r, abs_mag, redshift, Re_semimajor, sersic_n, and BA.
  • *_source_mstar_vs_photometric_properties.png: the same x axes against log10_mstar.
  • *_source_mass_bias_relations.png: log10 M_h versus log10 M_*, and bias_tinker10 versus log10 M_h.

These plots do not require rerunning selection. They only require the source catalog and the bias-assignment chain.

Important Caveats

  • Source-density blocker: the current GalSBI-SPS intrinsic catalog is too faint relative to F24 for the r < 28 SkyVar source cuts. F24 has r-band int_mag median about 26.65; the one-pixel SPS smoke has median about 29.83.
  • Production density decision pending: either find/build a magnitude-limited SPS generation path that reproduces F24 post-cut density, or use F24 density for n_pop and SPS only for stellar-mass and bias properties.
  • The current science path uses actual SPS surviving stellar mass. Apparent photometry is not converted to mass except in explicitly requested diagnostic luminosity-proxy runs.
  • The 0.15 dex scatter is a modeling choice, not an SPS measurement.
  • The default SHMR and bias paths are interpolation approximations. Exact modes exist but are slower and are not the active production settings.
  • The source catalog after cuts should be regenerated after the source-density decision. Old fixed-cap source pools are not valid for density calibration.
  • Selected high-redshift bins should be interpreted with selected-count and selected-weight masks, because small selected weights can amplify noisy extrema.
  • The classifier determines detection/selection and can induce photometry-dependent bias variation by preferentially selecting galaxies of different redshift, stellar mass, halo mass, and bias.
